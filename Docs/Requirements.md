# 要件定義: ちょこっと整体 予約システム

出張整体向けの、日本人向け予約 Web サービス。  
管理者が開催（日付・時間帯・コマ）を決め、ランダム URL を予約希望者に伝える。希望者はその URL から空きコマを選んで予約する。

対象読者: このリポジトリで実装する開発者（本ドキュメントが仕様の正）。

---

## 1. 目的

- 出張整体の当日枠を、紙や口頭ではなく Web で先着予約できるようにする。
- 予約者の操作は「空きコマを選ぶ → 3項目を入れる」だけにする。
- 予約が取れたら、予約者と管理者の両方にメールで残す。

## 2. 対象外（今回やらない）

- オンライン決済
- 予約者自身によるキャンセル・変更（変更は管理者へ連絡）
- 開催場所・注意書き・開催タイトル
- 入居者番号
- 複数管理者・招待
- ファイルアップロード（画像・PDF）
- Turso（データも認証も Supabase に統一）
- LINE / Google カレンダー連携
- 多言語・多タイムゾーン

## 3. ユーザー

| 役割 | 人数 | 認証 | できること |
| --- | --- | --- | --- |
| 管理者 | 1人 | Supabase Auth（メール＋パスワード）。初回アクセス時に自分でアカウント作成 | 開催の作成、予約一覧、予約取消、予約 URL の確認 |
| 予約者 | 不特定 | なし（URL を知っている人だけ） | 空きコマの予約 |

初回の管理者登録が完了したら、以降の新規登録は受け付けない。

## 4. 開催（イベント）

- **1開催 = 1日のみ**。複数日を1つの開催にはしない。
- 同時に複数開催を持てる。それぞれ別の予約 URL を持つ。
- 管理画面では過去の開催も含めて一覧できる。
- 開催の識別は **日付** で行う。タイトルは持たない。
- 開催作成時に次を入力する。
  - 日付
  - 受付開始時刻（この時刻から最初のコマが始まる）
  - 受付終了時刻（この時刻までに収まるコマだけ生成する）
  - 1コマの分数（開催ごとに入力。例: 20 / 30）
  - コマ間の休憩分数（開催ごとに入力。0 分可）
- 1コマの定員は **1人**。同時施術はない。
- コマは作成時にシステムが自動生成して保存する。手入力では作らない。
- 開催の編集はしない。作り直す。
- 開催の削除はできる（確認のうえ、紐づくコマ・予約も消す）。

### 4.1 予約受付の締め切り

開催の **開始日時（日付 + 受付開始時刻）を過ぎたら**、その開催の新規予約は受け付けない。  
開始後の空きコマがあっても予約不可。画面には受付終了と出す。

## 5. 予約 URL

- 開催ごとに推測されにくいランダムトークン付き URL を発行する。
- 形式: `/r/{token}`
- パスワードは付けない。URL を知っている人が予約者。
- 管理画面からコピーできる。
- 無効化専用の操作は持たない。開催削除、または開始日時超過で実質クローズ。

## 6. 予約者の操作

1. 管理者から URL を教えてもらう。
2. 画面に並んでいるコマから、空いているものを1つ選ぶ。
3. 予約者情報を入力して送信する。
   - 会社名（必須）
   - 名前（必須）
   - メールアドレス（必須）
4. 完了画面を見る。同時にメールが届く。

予約済みコマはグレーアウトし、選択できない。  
全コマが埋まったら満席と表示する。

### 6.1 同一人物

- **1開催につき、同一メールアドレスは1コマまで**。
- 判定キーはメールアドレス（大文字小文字は同一視する）。
- 別開催なら同じメールでも予約してよい。
- 連続コマの予約は、同一開催では不可。

### 6.2 予約者側にない機能

キャンセル、変更、マイページ、ログイン。

## 7. 管理者の操作

- ログイン / ログアウト
- 初回のみアカウント作成
- 開催一覧（新しい日付が上）
- 開催作成 → 生成されたコマの確認 → URL のコピー
- 開催詳細: コマごとの予約者（会社名・名前・メール・予約日時）
- 予約の取消。取消したコマは再び予約可能になる
- 開催の削除

管理者は予約内容の修正（名前の書き換えなど）はしない。取り消して予約者に取り直してもらう。

## 8. メール

送信は **Resend**。日本語。

| きっかけ | 宛先 | 内容 |
| --- | --- | --- |
| 予約が成立した | 予約者 | 開催日、コマの時間、会社名、名前 |
| 予約が成立した | 管理者 | 同上＋予約者メール |
| 管理者が予約を取り消した | 予約者と管理者 | 開催日、コマの時間、取り消した旨 |

管理者宛は、登録済み管理者アカウントのメールアドレス。

## 9. 技術

| 層 | 採用 |
| --- | --- |
| UI / API | Next.js App Router（本リポジトリ） |
| 認証・DB | Supabase（Auth + Postgres） |
| メール | Resend |
| 公開 | Vercel |
| 言語・時刻 | 日本語 UI、タイムゾーン `Asia/Tokyo` |

当初候補だった Turso と Supabase Storage（ファイル）は使わない。

## 10. 品質・見た目

- スマホでも PC でも使える。予約画面はスマホ利用を優先する。
- 操作は少なく、説明文は短くする。
- 二重送信や同時予約で同じコマが2件にならないこと。
- 個人情報（名前・会社名・メール）は予約通知と管理画面以外に出さない。
