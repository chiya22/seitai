# 決定事項と仮定

Requirements.md に書いたこと以外で、実装を止めないためにここで固定する。  
覆すときはこのファイルと Requirements.md を両方直す。

## ヒアリングで確定したもの

| ID | 内容 |
| --- | --- |
| D1 | 1開催は1日のみ |
| D2 | 1コマ1人 |
| D3 | コマ間休憩あり。分数は開催ごとに入力（0可） |
| D4 | 予約者自身のキャンセル・変更はなし |
| D5 | 1開催1メール1コマ |
| D6 | 管理者は1人。初回画面で自分で登録 |
| D7 | 締め切りは開催開始日時 |
| D8 | 決済なし |
| D9 | 複数開催を同時に持てる。管理画面では過去も見る |
| D10 | 同一人物判定はメールアドレス |
| D11 | 管理者は予約取消ができる |
| D12 | 開催項目は日付・開始・終了・コマ分数・休憩分数のみ |
| D13 | メール送信は Resend |
| D14 | データも認証も Supabase。Turso は使わない |
| D15 | 予約項目は会社名・名前・メール（すべて必須）。入居者番号は廃止 |
| D16 | 開催タイトルなし。日付で識別 |
| D17 | 1コマの長さは開催ごとに入力 |
| D18 | 取消時は予約者と管理者の両方にメール |
| D19 | デプロイは Vercel |

## 未指定だった点の仮定

| ID | 仮定 | 理由 |
| --- | --- | --- |
| A1 | 開催の事後編集はしない | コマ再生成と既存予約の衝突を避ける |
| A2 | 開催削除時は予約・コマも削除する | 管理者が作り直す前提 |
| A3 | 予約取消は論理削除（`cancelled_at`） | 同じコマの再予約と「1メール1件」を両立するため |
| A4 | コマ行は開催作成時に DB へ保存する | 予約の一意制約を DB で担保するため |
| A5 | データ操作は Next.js の Server Actions 経由。ブラウザから DB を直接書かない | 匿名予約でもバリデーションをサーバで完結させる |
| A6 | 管理者の新規登録は「ユーザーが0人のときだけ」許可 | 公開 URL から第二管理者が作られないようにする |
| A7 | メールの From は Resend で検証済みのドメイン（環境変数） | 未定のため実装時に `.env` で持つ |
| A8 | トークンは URL 安全な 21文字以上（nanoid 相当） | 推測困難にする |
| A9 | トップ `/` はサービス名＋管理者ログインへの導線。予約は URL 直アクセスが主 | 予約者にトップを見せる必要がない |
| A10 | 同一日付に開催を複数作れる | 禁止する要件がなかった。一覧は日付＋開始時刻で並べる |
| A11 | 予約画面のコマは開始時刻の昇順 | 操作を単純にするため |
| A12 | 受付終了時刻ちょうどに終わるコマは作ってよい。はみ出すコマは作らない | 終了時刻を守る |
| A13 | 同時押しは DB のユニーク制約で落とし、後着にエラーを返す | グレーアウトだけではレースを防げない |
| A14 | フォント・色は読みやすさ優先のシンプルな日本語 UI。ブランド指定なし | 未指定 |
