# 画面仕様

文言は実装時に多少整えてよい。項目と分岐は守る。

## 共通

- `lang=ja`
- 予約系はモバイル優先。余白を詰めすぎない
- 送信ボタンは処理中に二重押し防止

---

## `/` トップ

- サービス名「ちょこっと整体 予約システム」
- 短い説明（出張整体の予約用）
- 「管理者ログイン」→ `/login`
- 予約者向けの入口は置かない（URL 直アクセス）

## `/signup` 初回登録

- メール、パスワード、パスワード確認
- すでに管理者がいる場合は登録せず、`/login` へ誘導
- 成功後は `/admin`

## `/login`

- メール、パスワード
- 成功後は `/admin`
- ユーザーが0人なら「初回はアカウント作成」→ `/signup`

## `/admin` 開催一覧

- ログアウト
- 「開催を作る」
- 各行: 日付、開始〜終了、コマ数、有効予約数 / コマ数、受付中 or 終了 or 満席
- 行クリックで詳細

## `/admin/events/new` 開催作成

フォーム:

| 項目 | 入力 |
| --- | --- |
| 日付 | date |
| 開始時刻 | time |
| 終了時刻 | time |
| 1コマ（分） | 正の整数 |
| 休憩（分） | 0 以上の整数 |

送信前または直後に、生成されるコマ一覧を見せる（作成確定前にプレビューできるとよい）。  
1コマもできない組み合わせはエラー。  
成功後は詳細へ。URL をすぐコピーできるようにする。

## `/admin/events/[id]` 開催詳細

- 日付、時間帯、コマ分、休憩分
- 予約 URL とコピーボタン
- コマ表: 時刻、空き / 予約者（会社・名前・メール）、予約時刻
- 有効予約がある行に「予約を取り消す」（確認ダイアログあり）
- 「この開催を削除」（確認ダイアログ。取り消せない旨を書く）

## `/r/[token]` 予約

トークン不正: 「この予約ページは見つかりません」

開催開始済み: 「予約の受付は終了しました」

それ以外:

- 開催日と時間帯
- コマ一覧。空きはボタン、予約済みはグレーで押せない
- 満席なら「満席です」
- 選択中のコマを明示
- 会社名、名前、メール
- 「予約する」

エラー例:

- そのコマは直前に埋まった
- このメールアドレスでは既に予約済み
- 入力不備
- 受付終了

成功したら `/r/[token]/complete` へ。選択コマがクエリで残らなくてよい（完了文面に時刻を出す）。完了画面に出す内容はサーバ側の予約結果を渡す。

## `/r/[token]/complete`

- 「予約を受け付けました」
- 日付、コマ時刻、会社名、名前、メール
- 確認メールを送った旨
- 同じ開催で追加予約する導線は出さない（1人1コマのため）
